# dagny and Materialize behaviours that bite themes

Each entry: where it shows, why it happens, the fix that is known to work (all fixes live in
`organizers/3162/events/84219/styles.css` unless noted). Selectors are dagny's own; copy them exactly.

## Page hooks on `<body>`

- `eventPage.jsp` (event and show pages): `<body id="st-container" class="event-page" data-eventid="…" data-organizerid="…">`; `travelEventPage.jsp` has the same id, class and `data-eventid`.
- `organizerPage.jsp`: `<body data-organizerid="…">` — no `data-eventid`, no class; the page is also the only one with `#organizer-calendar` in the markup.
- `travelPage.jsp`: `<body class="bg-light" data-organizerid="…">`.
- Use them to scope organizer-level rules: `body:not([data-eventid]) …` for "not on an event or show page", `body.event-page …` for the opposite. Attribute selectors and `:not()` work everywhere, so prefer them over `:has()` for this.

## Hero (`section#top`, `div#main-ribbon`)

- **Blue stock photo behind everything.** `#background-container` is `position: fixed` with an inline `background-image` from the image API (the event's image, or dagny's fallback), and `fadeBanner()` in `eventPage.js` writes inline `filter`/`transform` while scrolling. Fix: `section#top #background-container { background-color: <surface>; background-image: none !important; filter: none !important }` and paint the hero with `section#top::before { content: ''; position: absolute; inset: -80px 0 0 0; z-index: 2; pointer-events: none; background: <gradient> }`. Keep the fixed layer when the event has a real photo you want.
- **Huge empty space above the title.** dagny reserves 35–75 % of the width as `padding-top` on `div#main-ribbon` to show the photo. Set a fixed `padding-top` (110 px desktop, 84 px mobile worked) when the photo is gone.
- **Logo above the title.** `div#main-ribbon::before { content: ''; display: block; width: min(460px, 78vw); aspect-ratio: <w> / <h>; background: url(...) no-repeat left center / contain }`.
- **Info chips.** `div#main-ribbon .event-info` has `color: white !important` (match it with your own `!important`), `text-transform: uppercase`, and `> i.material-icons { margin-right: 18px }`. A mono label face makes the 18 px plus the space look detached; 6 px reads right.
- **Grey scrollbar under the chips.** The chips sit in `#event-info-slider-wrapper.slider-wrapper` (`overflow-x: auto`); on small screens dagny gives it negative margins, and any overflow draws a classic scrollbar. `div#main-ribbon .slider-wrapper { scrollbar-width: none }` + `::-webkit-scrollbar { display: none }` keeps it scrollable and hides the bar.
- **Which chip is which.** In `topSection.jsp` the chips are: playtime (only when the shows have a common length), city count ("1 Ort"/"1 City"), date span. The date span is always `:last-child`, so `div#main-ribbon .event-info:not(:last-child) { display: none }` keeps just the dates as a label above the title (Sofiero).
- **The event description moves.** When the event has a calendar (`.filter-calender-base`), `event.js` moves `.event-information` and the "Läs mer" `.event-information-button` from `section#top` into `#flex-info-wrapper`, the column next to the calendar. Style both places (`section#top div.event-information, #flex-info-wrapper div.event-information`). `.minimized` is a 100 px box with a fading mask; the button is `display: none` inline until JS finds the text overflowing. dagny's own background for the expanded text is `rgba(0,0,0,.45)`: set `background: none` and `padding: 0 !important`.
- **`.filter-calender-base` is `flex-flow: row wrap-reverse`.** When it wraps, the description lands above the calendar; an `order` you add flips that. Stack explicitly on narrow screens (`flex-direction: column`) instead of relying on the wrap.
- **Header and back arrow.** `header#main-header` is `position: absolute`, 80 px, transparent over the hero. The back arrow `a.back-to-organizer` is `position: fixed` at x 10–54 and stays there while you scroll (with a dark round background), so a logo in the header goes after it: `header#main-header::before { left: 70px }`. The strip above `<main>` shows `body`'s background once the hero no longer paints it.
- **The event image as a photo row instead of a fixed backdrop.** `section#top #background-container { position: absolute; inset: 0 0 auto 0; height: <row>; min-height: 0; background-image: url(…) !important; filter: none !important; transform: none !important }` (the image is set in a `<style>` block in `topSection.jsp`, twice with a mobile variant; `fadeBanner()` writes inline `filter`/`transform`). Hide `.obfuscator`.
- **Lining up the title and the calendar.** The title (`div#main-ribbon > h1`) is in `section#top`, the calendar in `section#active-events`; in normal flow they cannot share a top edge without knowing the title's height. What works (Sofiero, section 4b): `body.event-page main:has(.filter-calender-base) { display: grid }` with named columns and rows, `display: contents` on `main > .container`, `section#top`, `div#main-ribbon`, `section#active-events`, its `.container`, the `.col.s12` and `.filter-calender-base`, then place `.slider-wrapper`, `h1`, `#flex-info-wrapper`, `#calendar-wrapper` and `#show-listing` in the grid. A full-bleed band behind them is `main::before` as a grid item. Traps: the empty `a#read-more` becomes a grid item (take it out of flow with `position: absolute`); an `order: -1` left from a flex layout paints that item under `main::before`; a `1fr` row after the title rows absorbs the calendar's extra height so the title block does not stretch. No dagny JS measures those wrappers on the event page: `scrollBodyToElement('#active-events')` is only called from `#arrow-container`, which this layout does not render.

- **Without a calendar the description stays in the hero.** On events without "Visa kalender" (Parken Zoo Säsongskort, Grand Stade) `.event-information` and its button stay in `div#main-ribbon`, after the `h1`. The ribbon also holds the organizer's tags as `a.n-chip.theme-background-color.no-function` siblings of the `h1` (and `body.has-organizer-tags` changes dagny's `padding-top` on the ribbon), the empty `a#read-more` and a hidden input.
- **Two hero layouts that work without a calendar.** (1) Flatten the ribbon: `section#top { display: grid }` with named rows, `div#main-ribbon { display: contents }`, and place `#background-container` (as a photo row, `position: relative`), `.slider-wrapper`, `h1`, `.event-information` and the button in the grid (Parken Zoo 86041). Only for events without tags: every `a.n-chip` becomes its own grid item. (2) Keep the ribbon whole as a panel and grid only `section#top`'s two children, `#background-container` and `div#main-ribbon`, side by side on desktop and stacked on phones (Grand Stade 85791). This works with tags, and the panel grows naturally when the description is expanded; align the grid to `start` so the image does not drift to the middle of a tall panel.
- **dagny's padding and heights to undo for a photo row or framed image.** `div#main-ribbon` gets `padding-top` 35 % (≥ 992 px), 40 % (≤ 991 px) and 75 % (≤ 600 px), halved with `body.has-organizer-tags`; `body section#top div#main-ribbon.container` beats all of them. `section#top #background-container` gets `padding-top: 75%` on phones and `min-height: 114vh`, `140vh` (≤ 320 px) or `150vh` (short landscape screens); set `padding: 0; min-height: 0` and give it its size with `aspect-ratio` or grid rows.
- **`div#main-ribbon p` is white, 18 px, with a text shadow**, directly on the `p`. A description on a light surface needs `div#main-ribbon div.event-information p { color: …; font-size: inherit; text-shadow: none }`.
- **The phone image is a separate crop.** dagny's `<style>` switches `#background-container` to `…/organizer/<org>/event/<event>?redirect&type=mobile` below 700 px. When that crop is poor (Grand Stade's cut a different graphic in half), an event stylesheet can point phones at the desktop image: `@media (max-width: 700px) { section#top #background-container { background-image: url('https://branding.nortic.io/organizer/<org>/event/<event>?redirect') !important } }`. The URL always serves the event's current image.
- **The strip above `<main>` is dagny's `nav#menu-2`, 64 px of `#121212`.** A header lower than 64 px leaves a dark band between it and the hero: make `header#main-header` 64 px (with `> .row { height: 100% }` so the icons stay centred) and give `body` the header colour.
- **"Läs mer" / "Dölj" under the description.** `event.js` `addReadMoreButtonListener()` shows the button when `#event-information-text` is taller than `minimizedDescriptionHeight` (a global `var`, 100). Clicking removes `.minimized` and calls `slideDown()`; clicking again runs `slideUp()` and stops when the height is at most 100, then sets `height: 100px` inline and adds `.minimized` back. A themed `.minimized` height of anything else therefore jumps on collapse (and with `!important` the next expand starts from the stale inline 100 px). Keep 100 px; a companion `script.js` can set `window.minimizedDescriptionHeight` to the CSS height (it runs after the deferred `event.js` and before `document.ready`), but the user preferred no script.
- **The "Läs mer" button bounces away from the pointer.** dagny animates it on hover: `section#top div.minimized + a.event-information-button:hover { animation: hintDown 1s }` and `section#top a.event-information-button:hover { animation: hintUp 1s }`, 5 px. On dagny's 36 px button that is harmless; restyled as a ~26 px text link, a click near the top edge lands after the link has moved and is lost, so the first click "does nothing" and the second works. Fix: `animation: none` on both selectors, `padding-top: 14px; margin-top: -14px` for a 40 px hit area, and `.waves-ripple { display: none }` (Materialize's click ripple draws a grey box behind a transparent button). The "Dölj info" translation can be all caps (`data-text-triggered`); `text-transform: lowercase` plus `::first-letter { text-transform: uppercase }` makes both states match.
- **The description's line breaks cannot be tidied in CSS.** Organizers write lists as `- Djurparken<br><br>- Tivolit…`. `br + br` does not mean "two `<br>` in a row": the sibling combinator skips text nodes, so it matches almost every `<br>` and the whole text runs together. Leave the breaks and ask for the text to be edited in the admin if the blank lines bother the customer.

## Calendar (`.filter-calender-base`)

- Days are `li` with a `::before` disc: `.days li.selectable::before`, `.selectable.bookable::before`, `.bookable.half-sold::before`, `.calendar .days li.selectable.selected::before`, hover variants `.selectable:not(.selected):hover::before` and `li:not(.selectable):hover::before`. Colour those, not the `li`.
- The card is `#calendar-wrapper > div`; give it `position: relative` if you add a decorative `::before` (ribbon) and push `.wrapper .calendar-header` down with `padding-top` to make room.
- **Square days.** `.calendar .weeks` and `.calendar .days` are flex rows of `li` at `width: calc(100% / 7)` with `margin-top: 30px`; the disc is a 40 px `::before` centred with `translate(-50%, -50%)` (35 px below 430 px, with the `li:before` spelling). For squares: make both lists `display: grid; grid-template-columns: repeat(7, minmax(0, 1fr)); gap: 3px`, give the `li` `width: auto; margin-top: 0; aspect-ratio: 1` and the `::before` `inset: 0; width: auto; height: auto; transform: none; border-radius: 0`. In a wide calendar (a 50 % column on desktop) `aspect-ratio: 1` gives 80+ px cells; use a fixed `height` above 900 px.
- **Month arrows.** `#cal-prev`/`#cal-next` are 38 px spans with `line-height: 38px` around a 24 px icon, which sits high once you add a border. Centre with `display: flex; align-items: center; justify-content: center` and give the `i` `display: block; line-height: 1`. `.disabled` is `opacity: .25`; if one arrow is filled, reset the disabled one to the outlined look.
- `.days li.inactive` (days of the neighbouring months) is `opacity: 0`; leave it.

## Show listing (`section#active-events #show-listing`)

- Month rows are `.show-listing-month` with `.month-name`; the calendar also toggles a hidden `.show-listing-month.fake-month` ("Välj datum i kalender…") from JS. To drop month headings use `.show-listing-month:not(.fake-month) { display: none }` and give the element above (e.g. a ribbon `::before`) a bottom margin for the spacing the row provided.
- `.sold-out-box` gets `.theme-background-color` from JS: use `!important` for its background and colour.
- Not-released and not-bookable shows get `opacity: 0.3` on their date ball, arrow and texts from dagny; leave that alone.
- **With a calendar, the month headings are hidden by JS.** `event.js` adds `.display-none` to every `.show-listing-month:not(.fake-month)` and filters the rows to the selected day. A theme that gives `.show-listing-month` a `display` shows them again unless `.display-none` is repeated with `!important` (Billy Elliot section 4).
- **Rows as a grid.** `.show-listing-show > .row.valign-wrapper` can take `display: grid` (Billy Elliot, Sofiero): the columns are `.dateball-container`, `.large-screen-date`, `.show-name-container`, `.price-range`, `.location-med-and-up`, `.show-listing-arrow`. Reset Materialize on each (`float: none; width: auto; margin-left: 0; padding: 0; min-height: 0`). On phones dagny renders other columns: `.dateball-container`, `.combined-name-and-info` (name, `<br>`s, price, `.show-info-small`) and `.showcalander-btn-wrapper`, and it locks `.col.dateball-container:first-of-type` to 18 px.
- **Sticky month headings** need `body#st-container.event-page { overflow-x: clip !important; overflow-y: visible !important }`: dagny puts `overflow: hidden !important` on it for the off-canvas menu, which kills `position: sticky`.
- **Supply dots as a meter.** `.supply-blobs .supply-blob` are five spans; the filled ones also carry `.supply-left.theme-background-color-override` (the organizer colour with `!important`). Size them (`width: 18–26px; height: 4–5px; border-radius: 0`) and give the unfilled ones a neutral background.
- **The weekday** in `.large-screen-date` is `span.capitalize.bold`, followed by text nodes for date and time; it can be styled as a label, the rest cannot be split.
- **A show without a date** (season pass) has `i.no-date-show.material-icons` ("event_available") in its `.dateball` and an empty `.large-screen-date`. Another icon can replace it on the pseudo-element: hide the `i` and use `.dateball:has(.no-date-show)::before { content: 'star'; font-family: 'Material Icons'; font-feature-settings: 'liga' }` (a font on a pseudo-element is fine; a font on the `i` is not).
- **The phone arrow button.** `.showcalander-btn-wrapper` has `margin-top: 20px !important`, so it sits lower than the name unless you override with `!important`; and the `a.btn` inside shrinks to 25 px in a narrow grid column unless it gets `flex: 0 0 <size>; min-width: <size>`.

## Ticket cards (unnumbered shows, `.unnumbered-show-container`)

- Category cards: `.show-category-row .show-category-container .show-category`, and the same with `:has(div.available-at)` for categories with a later release date (dagny paints those lighter).
- **Ring behind the "Släpps <date>" chip.** `div.available-at` is absolutely positioned over the `.amount-blob-container`; dagny relies on the blobs being white on white. Any border or tint on `.amount-blob.amount` or `.amount-blob.disabled` peeks out. Fix: `.booking-contents .amount-blob-container:has(> .available-at) .amount-blob { visibility: hidden }` (keeps the layout height).
- `.amount-blob.disabled` has an `!important` grey in dagny; override with `!important`.
- `a.btn.open-addons` has an inline black background: `!important`.
- **Card with a quantity.** dagny removes `.disabled` from the minus blob as soon as the category has tickets, so `.show-category:has(.amount-blob.minus:not(.disabled))` marks the chosen cards without JS.
- **Card geometry to undo for a list or a different grid.** `.show-category-container` is `width/min-width: 240px; min-height: 245px; margin: 10px`, `.show-category` is a flex column with `min-height: 245px` and `justify-content: space-between`, `.show-category-info` has `min-height: 64px`, and below 992 px `.show-category-row` scrolls horizontally (`overflow-x: scroll`) with `.show-category-scoll-wrapper { flex-wrap: nowrap; min-width: 100%; float: left }`. For a list (Parken Zoo) or a responsive grid (Grand Stade): `overflow: visible` on the row, `display: grid` on the wrapper (`repeat(auto-fill, minmax(min(100%, 250px), 1fr))`), reset the container sizes, and hide `.category-slider`, which has nothing to scroll any more. The `.col` children of `.show-category` can be placed in a grid with `> .row.no-margin`, `> .col:has(.list-price)` and `> .col:has(.amount-blob-container)`.
- **Steppers shrink between 991 and 1150 px.** dagny sets `.amount-blob` to 27 px there with `section#active-events .container .booking-contents.unnumbered-show .show-category-container .col .amount-blob`; size yours with that selector plus `.plus`/`.minus` to win everywhere.
- **The title row** ("Välj antal biljetter och kategori" and "Använd kampanjkod") is `.row.title-row`, padded by `section#active-events .container .booking-contents.unnumbered-show .title-row` (one class more than you would guess). Made a flex row, Materialize's clearfix `.row::after` becomes a third flex item and pulls `space-between` apart: `::after { content: none }`.
- **Sold out.** Every card carries `.sold-out-banner-container > .sold-out-banner` ("Slutsåld"), `display: none` in CSS; `eventPage.js` shows it with an inline `display: flex` on sold-out categories, so `.show-category:has(.sold-out-banner[style*='flex'])` is the sold-out card. The banner is a corner ribbon (`rotate(90deg) … rotate(-45deg)`) in a 107×76 px `overflow: hidden` container; for another shape (a rubber stamp at Grand Stade) set the container to `width/height: auto; overflow: visible` and position it, and put it where the steppers were (they are disabled; `visibility: hidden` keeps the height) so a long room name is never covered.
- **"Fåtal kvar!"** is `.indicator-limit.absolute-right` (in the price column, positioned against the card at `top: -8px; right: 8px`): an orange gradient pill with white text and an `i` icon hanging out at `top: -9px`. Restyle the pill and hide the icon for a clean tag.
- **"Kampanj" on categories unlocked by a campaign code.** `eventPage.js` generates those cards (`.show-category-container.generated-by-campaign-code`) with `<div class="campaign">` inside `.show-category`: green, `position: absolute; top: -14px; right: -8px`. In a list row it lands across the row line and outside the right edge; give it a grid row of its own above the name (`position: static`, Parken Zoo) or a tag on the card's top edge (Grand Stade). Selector: `section#active-events .container .booking-contents.unnumbered-show .show-category > .campaign`. There is no campaign code to test with; inject the generated markup (copied from `eventPage.js`).
- **"LÄS MER" in a category's text** is `.read-more-info-link`; it opens `openNorticModal('info', name, fullInfo)`, i.e. a `.nortic-modal`, themed with the small modals.
- **Closing the checkout leaves the chosen amounts (dagny bug).** `event.js` `modal:close` runs `resetBasket()` (pill to 0) and cancels the temporary order, but not `resetShow()`: the cards still show "1", the order tracker keeps the ticket, and the next "+" makes it 2 tickets at double the price. Same with and without a theme; the fix belongs in EventSystem (`resetShow(lastOrderTracker.showId, lastOrderTracker.sectionId)` next to `resetBasket()`). A theme that tints chosen cards makes the stale state more visible, not worse.
- **Carousel arrows on phones.** Below the large breakpoint the cards scroll horizontally and dagny adds `.category-slider` (`#card-scroll-action-left/right`) with `a.btn-floating.white.addons-slider`. Materialize's `.white` is `background-color: #fff !important`, and dagny gives the `i` its own white background and `#31389e` colour. Theme: `.unnumbered-show-container .category-slider a.btn-floating.addons-slider { background-color: <c> !important }` and `… i.material-icons { background-color: transparent; color: <on-c> }`. Without the `!important` the icon takes your light colour on the white button and disappears.

## Buttons and theme classes

- `.theme-background-color`, `.theme-secondary-background-color`, `.theme-color`, `.theme-secondary-color` come from the organizer's stored theme colours and are applied to buttons, blobs and chips; `.theme-background-color-override` / `.theme-text-color-override` are used with `!important` by dagny (supply blobs, JS modals) — override them with `!important` too.
- `div#add-to-basket-cart .btn` is hard-coded orange (`#ffb53e`); `div#basket-cart:hover` and `div#basket-cart-go-to-payment:hover` are hard-coded `#5966a9`. Restyle default and hover together.

## Floating basket (`div#basket`, `div#basket-cart`, `div#addons-basket`)

- `div#basket` is a fixed 170 px pill whose `.price-container` is 60 px wide at `right: 45px`; a price like "200 SEK" collides with the arrow circle. Fix: `div#basket { width: 224px }` and `div#basket .price-container { left: 58px; right: 58px; width: auto; justify-content: center; text-align: center; white-space: nowrap }`.
- `div#basket-overlay` is the circle that scales up (`transform: scale(5)`) to cover the page while the order is created — locally that takes ~10 s, so its colour matters. Give it the theme's darkest colour.
- **Basket-cart buttons** (organizers with `data-organizercart="true"`; markup in `priceBlobBasketCart.jsp`): `#basket-cart` ("Varukorg", `.amount-blob` with `span.icon > i` `shopping_cart` and `.chip.amount` for the count) and `#basket-cart-go-to-payment` ("Till kassan", `.payment-blob` with `i` `payment`, plus `.proceed-arrow-blob`). Both are 56 px high; the blob is 50 px at `top/left: 3px` with the icon at `top/left: 13px`. With square buttons that reads cramped, and a smaller blob with the 24 px icon reads cramped the other way. What the user accepted (Sofiero): blob 44 px at 6 px, icon `font-size: 20px` at `top/left: 12px`, count chip `min-width/height: 22px; padding: 0 6px; line-height: 22px` at `top: -7px; right: -9px` with a 2 px ring in the button colour. Never put `font-family` on the `i` in these buttons (see SKILL.md).
- **"Din order" overview** (`#cart-overview-modal`, `basketCartOverview.jsp` + `basketCartOverviewContent.jsp`): a Materialize `.modal` outside the checkout. The counters are `.shopping-cart-overview-section-header span` (`#303d9b`, radius 2 px), rows are `.shopping-cart-overview-tickets .detail-container` with `.list-title`/`.list-info` (grey)/`.list-price`, the trash is `.shopping-cart-delete-sub-order i` (turns `#cb1b1b` on hover). Buttons: `#basket-cart-overview-go-to-payment` (`.theme-background-color`) and `#basket-cart-overview-clear` (`.theme-secondary-background-color`, so both look primary unless you make "Töm varukorg" an outline). The dimmed page behind it is the global `.modal-overlay`, shared with the terms modals.
- The page also contains a hidden original `#basket-cart`/`#cart-overview-modal`; when you inject copies for a screenshot, query inside your own wrapper or you measure the hidden ones.

## Payment modal (`#material-modal`, `section#booking.payment-page.klarna`)

- The section has `style="background-color: #303d9b"`: `!important` on `background-color` (and `background-image` if the organizer file sets one).
- **Payment list jumps half a screen when it opens.** dagny centres `.payment-list` with `left: 50%; transform: translate(-50%, 0)`; the entrance animation `slideInUp` (animate.css, applied by `animateIn()` in `event.js`) replaces that transform for 0.3 s, so the list slides in with its left edge at the middle and snaps left afterwards. Visible in every theme, camouflaged only when list and overlay share a colour, and the first thing customers report — ship the fix in every theme. Fix (desktop only — below 600 px dagny skips the animation and centres with margins):

  ```css
  @media (min-width: 601px) {
    section#booking .booking-contents .payment-list.animated.slideInUp {
      animation-name: mf-payment-list-slide-in;
    }
  }
  @keyframes mf-payment-list-slide-in {
    from {
      transform: translate3d(-50%, 100%, 0);
      visibility: visible;
    }
    to {
      transform: translate3d(-50%, 0, 0);
    }
  }
  ```

- **Section header text overlapping.** `header.payment-section-header` is a Materialize `.row.valign-wrapper` (flex) with two fixed `col s6` columns; a wide heading face runs under the right-hand text ("Säkra betalningar"). Fix: `header { flex-wrap: wrap; gap: 4px 16px }`, `> .col.s6 { width: auto; flex: 0 1 auto; min-width: 0; margin-left: 0 }`, `> .col.s6:last-child { margin-left: auto }`. The `margin-left: 0` matters: Materialize gives every `.col` `margin-left: auto`, which in a flex row pushes the heading to the right.
- **Insurance row colours.** dagny: `.selection-row.selected` green `#50a752`, `.not-selected` red `#d04844`, and it also sets `background-color` on `.insurance-detail-container.selected .expandable-detail` (needs `!important` to neutralise). Classes update after the AJAX round trip; the radios update immediately, so key on `.selection-row:has(.yes [type='radio']:checked)` / `:has(.no [type='radio']:checked)` and list dagny's classes alongside. Customers expect "no" to stay red. A prefilled row carries both `.not-selected` and `.selected`, so the "yes" rule must come after the "no" rule. ## Materialize reminders

- `.row .col { margin-left: auto }` — harmless with floats, decisive inside any flex container you create.
- `.no-padding { padding: 0 !important }` — you cannot add padding to those columns; use `gap` or margins on the flex parent instead.
- Colour utilities carry `!important` too: `.white` (`background-color: #fff !important`), `.white-text`, `.transparent`. dagny uses `.white` on the carousel arrows; look for them in the markup when a colour will not change.
- `.modal-overlay` is one global element for every Materialize modal on the page (terms, insurance, "Din order"); its colour applies to all of them.
- `.valign-wrapper` is `display: flex; align-items: center`.
- On phones dagny gives `section#active-events .container` `width: calc(100% - 40px); margin: 0 20px`. A theme that sets its own container width must also set `margin: 0 auto`, or the listing sits 4 px off the hero above it.
- dagny's mobile breakpoint is `max-width: 600px` in CSS and `matchMedia('(max-width: 600px)')` in JS; use the same number.
